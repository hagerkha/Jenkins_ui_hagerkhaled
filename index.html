Day-by-Day Plan

Click each day to expand the detailed learning objectives and tasks

WEEK 01 — Foundations & Environment

🎯 Goal: Understand the landscape of Data Engineering before writing any code.

  • Data Engineering vs Data Science vs Data Analytics
  • ETL (Extract, Transform, Load) vs ELT patterns — when to use each
  • OLTP vs OLAP systems — differences in design and use case
  • Modern Data Stack overview (Ingestion → Storage → Transform → BI)
  • Draw your first data architecture diagram
📚 Resources: Fundamentals of Data Engineering (Reis & Housley)

🎯 Goal: Master the command line — a daily tool for every Data Engineer.

  • File system navigation: ls, cd, pwd, find, locate
  • File manipulation: cp, mv, rm, chmod, chown, ln
  • Piping and redirection: |, >, >>, 2>&1
  • Text processing: grep, awk, sed, cut, sort, uniq, wc
  • Bash scripting: variables, loops, conditionals, functions
  • Task: Write a bash script that processes a CSV, counts lines, extracts columns

🎯 Goal: Use Docker to create reproducible, isolated environments for your data stack.

  • Docker concepts: Images, Containers, Volumes, Networks
  • Writing a Dockerfile — COPY, RUN, CMD, EXPOSE, ENV
  • Docker Compose for multi-service stacks
  • Spin up PostgreSQL + pgAdmin with Docker Compose
  • Persist data using named volumes
  • Task: docker-compose.yml with PostgreSQL + seed data auto-loaded

🎯 Goal: Design data models that are efficient for analytics queries.

  • Normalization vs Denormalization tradeoffs
  • Star Schema: Fact tables vs Dimension tables
  • Snowflake Schema vs Star Schema — when to use each
  • Slowly Changing Dimensions (SCD Type 1, 2, 3)
  • Task: Design a Star Schema for a fictional e-commerce business with 5 dimensions

🎯 Goal: Write SQL that impresses interviewers and solves real analytics problems.

  • Common Table Expressions (CTEs) and recursive CTEs
  • Window Functions: ROW_NUMBER, RANK, DENSE_RANK, LAG, LEAD, NTILE
  • PARTITION BY and ORDER BY inside window functions
  • Indexing strategies: B-tree, Hash, Partial, Composite indexes
  • EXPLAIN ANALYZE for query optimization
  • Task: Solve 10 Hard SQL problems using CTEs and window functions

🎯 Goal: Build your first complete end-to-end ETL pipeline.

  • Download a real dataset from Kaggle (NYC Taxi or Brazilian E-commerce)
  • Write Python extraction script with pandas and proper error handling
  • Apply data transformations: type casting, deduplication, null handling
  • Load into PostgreSQL using SQLAlchemy with bulk insert
  • Add logging (Python logging module) and idempotency
  • Containerize the pipeline with Docker
  • Deliverable: GitHub repo with README, requirements.txt, docker-compose.yml

🎯 Goal: Learn to communicate technical designs clearly — a critical DE skill.

  • Writing great technical READMEs (structure, diagrams, setup instructions)
  • Architecture diagram tools: draw.io, Lucidchart, Mermaid.js
  • Document your Week 1 mini project properly
  • Add architecture diagram to GitHub repo
  • Week 1 review and knowledge consolidation
WEEK 02 — Spark & Data Lakes

🎯 Goal: Understand why distributed systems exist and their fundamental tradeoffs.

  • Why distribute? Horizontal vs vertical scaling
  • CAP Theorem: Consistency, Availability, Partition Tolerance
  • Data partitioning strategies: Range, Hash, List, Composite
  • Replication and sharding concepts
  • ACID vs BASE — consistency models in distributed systems

🎯 Goal: Understand Spark's architecture and why it's the backbone of big data processing.

  • Spark architecture: Driver, Executors, Cluster Manager, DAG Scheduler
  • RDDs (Resilient Distributed Datasets) — the foundation
  • DataFrames and Datasets — higher-level APIs
  • Lazy evaluation: transformations vs actions
  • SparkSession setup and configuration
  • Task: Load a 500MB CSV with PySpark and compare vs pandas performance

🎯 Goal: Build complex data transformation logic with PySpark.

  • DataFrame operations: select, filter, withColumn, drop, rename
  • Aggregations: groupBy, agg, pivot
  • Joins: inner, left, right, full outer, cross, semi, anti
  • Spark SQL — write SQL directly against DataFrames
  • UDFs (User Defined Functions) and their performance cost
  • Window functions in Spark

🎯 Goal: Write Spark jobs that run fast in production — a critical interview topic.

  • Understanding Shuffle — the biggest performance killer
  • Partitioning: repartition() vs coalesce()
  • Caching and persistence: cache(), persist(), unpersist()
  • Broadcast joins for small tables — huge performance gain
  • Spark UI for job monitoring and optimization
  • Avoiding common pitfalls: data skew, small files problem

🎯 Goal: Understand data lake architecture and why Parquet is the format of choice.

  • Data Lake vs Data Warehouse vs Data Lakehouse
  • Medallion Architecture: Bronze → Silver → Gold layers
  • Parquet format: columnar storage, schema, compression codecs
  • Other formats: ORC, Avro, Delta Lake — when to use each
  • Partitioning strategy for data lakes (date, region, category)

🎯 Goal: Build a production-style Spark data processing pipeline.

  • Read raw data from multiple CSV files in a folder structure
  • Apply cleaning, type casting, null handling transformations
  • Compute aggregations: daily totals, moving averages, rankings
  • Write output as partitioned Parquet (year/month/day)
  • Add data validation step with row count assertions
  • Deliverable: PySpark script + Dockerfile + README with architecture diagram

🎯 Goal: Consolidate Week 2 knowledge and document your Spark project.

  • Review Spark core concepts — fill any knowledge gaps
  • Write comprehensive README for your Spark project
  • Add architecture diagram showing data flow
  • Push to GitHub with clean, descriptive commit history
  • Prepare 3 interview questions about Spark you could be asked
WEEK 03 — Orchestration & Cloud

🎯 Goal: Set up Airflow and understand how to model workflows as DAGs.

  • Airflow architecture: Scheduler, Webserver, Executor, Metadata DB, Workers
  • DAG (Directed Acyclic Graph) concepts and structure
  • Core operators: BashOperator, PythonOperator, EmailOperator
  • Sensors: FileSensor, HttpSensor, S3KeySensor
  • Setting up Airflow with Docker Compose
  • DAG parameters: schedule_interval, start_date, retries, catchup

🎯 Goal: Automate your Week 1 ETL pipeline using Airflow.

  • Create a DAG that runs the CSV → PostgreSQL pipeline daily
  • Add task dependencies with >> operator
  • Handle task failures with on_failure_callback
  • Monitor execution in the Airflow UI (Graph view, Tree view)
  • Add a data quality check task using SQLCheckOperator

🎯 Goal: Master advanced Airflow patterns used in production systems.

  • XCom: passing data between tasks (xcom_push / xcom_pull)
  • TaskFlow API with @task decorator
  • Branching with BranchPythonOperator
  • Dynamic DAG generation with variables and connections
  • Retry logic, retry_delay, and exponential backoff
  • Connections & Hooks for external system integration

🎯 Goal: Get hands-on with the AWS services every Data Engineer uses daily.

  • S3: buckets, objects, prefixes, versioning, lifecycle policies
  • EC2: instances, security groups, key pairs, AMIs
  • IAM: users, roles, policies, least privilege principle
  • RDS: managed PostgreSQL, backups, parameter groups
  • AWS CLI and boto3 Python SDK
  • Task: Upload processed Parquet files to S3 with boto3

🎯 Goal: Understand cloud data warehouses and when to use them.

  • Columnar storage: why it's faster for analytics workloads
  • Distribution styles: EVEN, KEY, ALL (Redshift)
  • Sort keys and VACUUM/ANALYZE in Redshift
  • BigQuery: slots, reservations, partitioning, clustering
  • Cost optimization strategies for cloud warehouses
  • COPY command for bulk loading from S3 to Redshift

🎯 Goal: Build a cloud-native pipeline that mimics real production systems.

  • Source: Public API or dataset download
  • Ingest raw data to S3 (Bronze layer)
  • Transform with PySpark, save as Parquet to S3 (Silver layer)
  • Load aggregated data to Redshift/BigQuery (Gold layer)
  • Orchestrate entire flow with Airflow running in Docker
  • Deliverable: Full GitHub repo with architecture diagram and setup guide

🎯 Goal: Prepare for the technical portion of DE interviews.

  • Review all concepts from Weeks 1–3
  • Solve 5 Hard SQL problems on LeetCode/StrataScratch
  • Practice explaining your projects out loud (time yourself)
  • Review system design patterns for data systems
  • Prepare answers to top 20 DE interview questions
WEEK 04 — Streaming & Capstone

🎯 Goal: Understand Kafka's architecture and build your first producer/consumer.

  • Kafka concepts: Topics, Partitions, Offsets, Consumer Groups
  • Kafka architecture: Brokers, ZooKeeper/KRaft, Replication
  • Writing a Python Producer with confluent-kafka
  • Writing a Python Consumer with manual offset commit
  • Kafka retention policies and log compaction
  • Set up Kafka + Zookeeper with Docker Compose

🎯 Goal: Build a real-time streaming pipeline end-to-end.

  • Spark Structured Streaming fundamentals
  • Reading from Kafka source with Spark Streaming
  • Stateful transformations: aggregations over time windows
  • Output modes: append, complete, update
  • Write streaming results to PostgreSQL or Redis
  • Monitor streaming queries with query.status

🎯 Goal: Build a production-grade data platform showcasing all your skills.

  • Day 24: Ingestion — Batch API + Kafka streaming for real-time order events
  • Day 25: Storage & Transform — S3 Data Lake (Bronze/Silver/Gold) + Spark jobs
  • Day 26: Warehouse & Orchestration — Star schema in Redshift + Airflow DAGs
  • Day 27: Finalize — Dockerize everything, add monitoring, write tests

Architecture: Kafka → Spark Streaming → Bronze S3 → Spark Batch → Silver S3 → Airflow → Gold Redshift → Dashboard

🎯 Goal: Make your capstone project portfolio-presentable.

  • Write a comprehensive README (problem statement, architecture, setup, results)
  • Create a professional architecture diagram in draw.io or Lucidchart
  • Add screenshots of the running system and dashboards
  • Document key design decisions and tradeoffs
  • Write a LinkedIn article or blog post about your project

🎯 Goal: Get comfortable articulating your projects and knowledge under pressure.

  • Practice explaining your capstone in 2 minutes and 10 minutes
  • Conduct 2 full mock interviews (with peers or AI tools)
  • Practice whiteboard system design: "Design Twitter's data pipeline"
  • Behavioral questions using the STAR method
  • Research your target companies and tailor your answers

🎯 Goal: Launch your job search with a polished, professional presence.

  • Pin your 6 best repositories on GitHub profile
  • Write an outstanding GitHub Profile README
  • Update LinkedIn with all new skills and projects
  • Tailor your resume for Data Engineering roles
  • Apply to 10 positions today
  • Join DE communities: dbt Slack, Apache Airflow Slack, DE Discord
  • Celebrate! You earned it! 🎉

// INTERVIEW PREP

Common Interview Questions

Master these to confidently land your Data Engineering role

01

Explain CAP Theorem

A distributed system can guarantee at most two of: Consistency, Availability, Partition Tolerance. Systems like Kafka (AP) and PostgreSQL (CP) make different tradeoffs depending on their use case.

02

RANK vs DENSE_RANK?

RANK() skips rank numbers after ties (1,1,3). DENSE_RANK() doesn't skip (1,1,2). ROW_NUMBER() always assigns unique sequential values regardless of ties.

03

What is Shuffle in Spark?

Shuffle is data redistribution across executors, triggered by wide transformations (groupBy, join). It's the most expensive Spark operation — minimize it with broadcast joins and proper partitioning.

04

How does Airflow handle retries?

Via retries and retry_delay parameters at task or DAG level. Use retry_exponential_backoff=True for exponential delay and on_failure_callback to send alerts when tasks ultimately fail.

05

Fact vs Dimension Table?

Fact tables store measurable, quantitative events (orders, transactions) with foreign keys to dimensions. Dimension tables store descriptive attributes (customer name, product category) that provide context.

06

What is Idempotency?

An operation that produces the same result when run multiple times. Critical for data pipelines — if a job fails and reruns, it shouldn't create duplicates. Achieve with upserts, deduplication keys, and atomic writes.
